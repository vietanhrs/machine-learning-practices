# Anomaly Detection

Anomaly detection (also called **outlier detection** or **novelty detection**) is the
task of identifying data points, events, or observations that deviate significantly
from the expected pattern or normal behavior.

---

## 1. What is Anomaly Detection?

Given a dataset, anomaly detection asks: **which data points are unusual?**

Formally, given a set of observations X = {x_1, x_2, ..., x_n}, an anomaly is a
point x_i that is significantly different from the rest — it was generated by a
different process, is the result of an error, or represents a rare but important event.

**The core challenge:** "Normal" is rarely precisely defined. Models must learn what
normal looks like from data, often without labeled examples of anomalies.

---

## 2. Types of Anomalies

### Point Anomalies
An individual data point is anomalous compared to the rest of the dataset.

- Example: A single transaction of $50,000 when most transactions are $20–$200
- Most common type studied in the literature

### Contextual Anomalies
A data point is only anomalous given its context (time, location, etc.).

- Example: A temperature of 30°C (86°F) is normal in summer but anomalous in winter
- The value itself may not be globally unusual — context matters
- Also called **conditional anomalies**

### Collective Anomalies
A collection of related data points is anomalous even if individual points appear normal.

- Example: A series of small ATM withdrawals over one hour that together indicate fraud
- Sequence-level anomaly; requires looking at groups of observations together

---

## 3. Statistical Methods

### Z-Score (Standard Score)

For univariate data, the z-score measures how many standard deviations a point is
from the mean:

```
z = (x - μ) / σ
```

- **Threshold:** Points with |z| > 3 are flagged as anomalies (captures ~99.7% of normal data under Gaussian assumption)
- **Limitation:** Assumes data is approximately Gaussian; sensitive to the outliers themselves distorting μ and σ

### IQR Method (Interquartile Range)

More robust than z-score:

```
Q1 = 25th percentile
Q3 = 75th percentile
IQR = Q3 - Q1

Lower fence: Q1 - 1.5 * IQR
Upper fence: Q3 + 1.5 * IQR
```

Points outside the fences are flagged as anomalies (boxplot whiskers use this rule).
The IQR method is robust to outliers because it uses median-based statistics.

## 4. Isolation Forest

**Isolation Forest** (Liu et al., 2008) exploits the property that anomalies are
**few and different** — they are easier to isolate than normal points.

### How It Works

1. Randomly select a feature.
2. Randomly select a split value between the feature's min and max.
3. Recurse until each point is isolated (path length = number of splits needed).

**Key insight:** Anomalies are isolated in **fewer splits** (shorter path length) because
they occupy sparse regions of the feature space. Normal points cluster together and
require more splits to isolate.

### Anomaly Score

The anomaly score normalizes the average path length by the expected path length of a
random binary search tree on `n` samples:

```
c(n) = 2 * H(n-1) - 2(n-1)/n
```

where H(n) = ln(n) + 0.5772 (Euler-Mascheroni constant) is the harmonic number.

```
score(x) = 2^(-E[path_length(x)] / c(n))
```

- score ≈ 1.0 → very likely anomalous
- score ≈ 0.5 → normal
- score < 0.5 → far from anomalous

## 5. One-Class SVM

**One-Class SVM** (Schölkopf et al., 1999) learns a tight boundary around the normal
data in a high-dimensional (kernel) feature space.

### How It Works

- Training uses **only normal data** (no anomaly labels needed)
- Learns a hyperplane that separates normal data from the origin with maximum margin
- Uses the RBF kernel to handle nonlinear boundaries

### Anomaly Score

Points outside the learned boundary are classified as anomalies.

```
score(x) = sign(f(x))   where f(x) = w^T φ(x) - ρ
```

- f(x) > 0 → normal
- f(x) < 0 → anomaly

**Hyperparameter ν:** Upper bound on the fraction of training points treated as outliers
(analogous to a contamination rate).

**Comparison with Isolation Forest:**
- One-Class SVM: Works better in low dimensions; kernel choice matters; scales O(n²) with training size
- Isolation Forest: Scales well to large datasets; less sensitive to hyperparameters; works in high dimensions

## 6. Autoencoder-Based Detection

**Autoencoders** learn a compressed representation of the input by training to reconstruct it.

### Training Strategy

- Train the autoencoder **only on normal data**
- The bottleneck (latent space) forces the model to learn a compact representation of normal patterns

### Inference

- Compute **reconstruction error** for each new sample:
  ```
  error(x) = ||x - Autoencoder(x)||²
  ```
- Normal samples: low reconstruction error (model learned their pattern)
- Anomalous samples: high reconstruction error (model cannot reconstruct unseen patterns)

### Threshold Selection

- Set threshold at a high percentile (e.g., 95th or 99th) of reconstruction errors
  computed on the validation set
- Points with error > threshold are flagged as anomalies

**Advantage:** Works well in high-dimensional data (images, time series); can capture
complex nonlinear normal patterns.

## 7. Local Outlier Factor (LOF)

**LOF** (Breunig et al., 2000) is a **density-based** method that compares the local
density of a point to the local density of its neighbors.

### Key Concepts

- **k-nearest neighbors (k-NN):** For each point, find its k closest neighbors.
- **Reachability distance:** A smoothed distance metric to reduce noise effects.
- **Local reachability density (LRD):** Inverse of average reachability distance to k-NN.
- **LOF score:** Ratio of average neighbor LRD to the point's own LRD.

```
LOF(x) = (1/k) * Σ_{o in kNN(x)} [LRD(o) / LRD(x)]
```

- LOF ≈ 1 → point has similar density to neighbors (normal)
- LOF >> 1 → point is in a less dense region than neighbors (anomaly)

**Advantage:** Can detect anomalies in datasets with varying densities (unlike global
methods that assume uniform density).

## 8. Evaluation Challenges

Anomaly detection is notoriously hard to evaluate because:

1. **Few labeled anomalies:** Real anomaly datasets often have <1% positive examples.
2. **Label scarcity:** Labeling anomalies requires domain expertise and is expensive.
3. **Unknown anomaly types:** Models are tested on anomaly patterns they've never seen.

### Evaluation Metrics

| Metric            | Description                                                          |
|-------------------|----------------------------------------------------------------------|
| Precision         | Of flagged anomalies, what fraction are true anomalies?             |
| Recall            | Of all true anomalies, what fraction were caught?                   |
| F1 Score          | Harmonic mean of precision and recall                               |
| AUC-ROC           | Area under the ROC curve (threshold-independent)                    |
| Precision@k       | Precision among the top-k scored points (useful for ranked outputs) |
| Average Precision | Area under the precision-recall curve (better for imbalanced data)  |

**Note:** Accuracy is almost useless — a model that labels everything as "normal" achieves
99%+ accuracy if anomalies are 1% of data.

## 9. Applications

| Domain               | Use Case                                                              |
|----------------------|-----------------------------------------------------------------------|
| Financial Fraud       | Detect unusual credit card transactions                              |
| Network Security      | Flag unusual traffic patterns (intrusion detection)                  |
| Manufacturing         | Detect defective products on production lines                        |
| Healthcare            | Identify unusual patient readings or rare diseases                   |
| Predictive Maintenance| Detect early signs of equipment failure from sensor data             |
| E-commerce            | Flag fake reviews, bot activity, or account takeovers               |
